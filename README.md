# Federated Learning для детекції об'єктів (ArTaxOr)

Симуляція федеративного навчання на двох воркерах. Датасет: Arthropod Taxonomy Orders Object Detection (Kaggle).
Стратегії: **FedAvg, FedProx, FedAdam**. Для кожної перевіряються 4 випадки розбиття даних (усього 12 запусків).

## Що всередині

| Файл | Призначення |
|---|---|
| `inspect_dataset.py` | показує структуру датасету та формат анотацій |
| `prepare_data.py` | читає анотації, зменшує зображення, зберігає кеш `cache/dataset.pt` |
| `make_splits.py` | розбиття на двох воркерів у 4 режимах (`splits/*.json`) |
| `model.py` | Faster R-CNN MobileNetV3-Large FPN (ваги COCO, нова голова під наші класи) |
| `fl.py` | воркери, стратегії FedAvg/FedProx/FedAdam, цикл раундів |
| `evaluate.py` | власна оцінка mAP@0.5 та mAP@0.5:0.95 |
| `run_experiments.py` | запуск усіх 12 експериментів і побудова графіків |
| `plots.py` | візуалізація |
| `config.py` | усі параметри |

## Встановлення

1. Python 3.10+.
2. PyTorch з підтримкою CUDA. Команду для вашої системи візьміть на https://pytorch.org/get-started/locally/ (Pip, CUDA).
3. Решта пакетів: `pip install -r requirements.txt` (torch/torchvision, якщо вже стоять, перевстановлювати не треба).
4. Перевірка GPU: `python -c "import torch; print(torch.cuda.is_available())"` має вивести `True`.

Під час першого запуску torchvision завантажить ваги COCO (~75 МБ), тому потрібен інтернет.

## Запуск

Датасет завантажте з Kaggle вручну та розпакуйте. Нижче `ШЛЯХ` це папка з розпакованим датасетом.

```
python prepare_data.py --root "./ArTaxOr"         # 1. підготувати кеш (один раз)
python run_experiments.py --quick                 # 2. швидка перевірка, що все працює (1-2 хв)
python run_experiments.py                         # 3. повний прогін: 12 експериментів + графіки
```

Графіки можна перебудувати без повторного навчання: `python plots.py`.

## Результати

Усе в папці `results/`:

- `plots/splits_distribution.png`: скільки зображень кожного класу має кожен воркер у чотирьох режимах
- `plots/progress_map50.png`, `progress_map5095.png`: прогрес mAP по раундах (по одному графіку на режим, три лінії = три стратегії)
- `plots/progress_loss.png`: втрата навчання по раундах
- `plots/final_comparison.png`: фінальні mAP усіх 12 запусків
- `plots/per_class_ap.png`: AP по класах (видно, як модель справляється з класами, яких немає в одного з воркерів)
- `summary.csv`, `split_stats.csv`, `runs/*.json`: числа

## Режими розбиття

- **A**: однаковий розмір, збалансовані класи
- **B**: різний розмір (70% / 30%), збалансовані класи
- **C**: різний розмір (70% / 30%) і дисбаланс класів (у воркерів він протилежний)
- **D**: розміри однакові, у воркера 0 немає класів №0 і №1, у воркера 1 немає класів №2 і №3

Дані воркерів не перетинаються. Спільний тест (по `TEST_PER_CLASS` зображень кожного класу) не належить жодному воркеру,
на ньому оцінюється глобальна модель після кожного раунду.

## Як це працює

- Раунд: сервер розсилає глобальні ваги, кожен воркер навчається `LOCAL_EPOCHS` епох на своїх даних, повертає ваги, сервер агрегує.
- **FedAvg**: середнє вагів, зважене за кількістю зображень воркера.
- **FedProx**: те саме, але локальна втрата містить доданок `mu/2 * ||w - w_global||²` (`FEDPROX_MU` у `config.py`).
- **FedAdam**: сервер бере різницю між усередненими вагами та глобальними як псевдоградієнт і застосовує до неї Adam (`FEDADAM` у `config.py`).
- Backbone моделі заморожений, тому між воркерами та сервером передаються лише навчувані параметри (FPN, RPN, голова).

## Час роботи і налаштування

Орієнтовний час повного прогону 5-10 хв на GeForce 1660 (це оцінка, не вимір). Якщо виходить довше або коротше:

- `python run_experiments.py --rounds 3` або `--n-train 240`: швидше
- `--rounds 8 --local-epochs 2`: довше, але якісніше
- Постійні налаштування: `config.py` (`IMG_SIZE`, `PER_CLASS`, `BATCH_SIZE`, ...)
- Якщо змінили `PER_CLASS`, `TEST_PER_CLASS` або `IMG_SIZE`, заново запустіть `prepare_data.py`.
- Результати 12 запусків зберігаються окремо; повторний запуск пропускає вже виконані (якщо параметри ті самі). `--force` перезапускає все.
- Якщо не вистачає пам'яті GPU: `--batch-size 4`.

## Припущення та обмеження

- Для простоти розбиття по класах беруться лише зображення, де всі об'єкти одного класу (клас зображення = клас його об'єктів).
- Зображення зменшуються до `IMG_SIZE` по довшій стороні, а для експериментів береться підмножина датасету. Це зроблено заради часу, тому абсолютні mAP будуть нижчими, ніж при повному навчанні.
- Воркери симулюються в одному процесі й навчаються по черзі. Кожен має доступ лише до своїх зображень.
- Параметри FedProx/FedAdam не підбиралися ретельно, їх можна змінити в `config.py`.
